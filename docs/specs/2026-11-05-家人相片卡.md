# 家人相片卡 — 實作規格（2026-11-05）

依據 [docs/research/2026-11-05-家人相片卡.md](../research/2026-11-05-家人相片卡.md) 第 9 節的決定（選項 C）。本檔是 planner 方案的定稿版，實作完成後保留作紀錄；之後要改行為以 `CLAUDE.md` 程式地圖為準。

## 範圍

- 固定 8 個槽位：`family_dad`、`family_mom`、`family_grandpa`、`family_grandma`（固定稱呼，有預設語音退路）+ `family_custom1`～`family_custom4`（卡名固定「家人／Family」，不打字）。
- 照片只從相簿選：NativeGallery 1.9.5（OpenUPM，MIT）。iOS 走 PHPicker（行程外、零權限）；Android 走 `ACTION_GET_CONTENT` 並由 `PhotoPicker` 把 Java 端 `PermissionFreeMode`／`preferGetContent` 打開，不跳權限詢問。Editor 用檔案視窗，Play 模式可以測完整流程。
- 儲存：`Application.persistentDataPath/family/{id}.jpg`（長邊 ≤ 1024、品質 85）＋ `{id}.wav`（家長錄的稱呼，一段通用、不分語言）。不做帳號、不同步。
- 家長入口：設定頁底部「家人卡」鈕 → `FamilyEditScreen`（8 格 4×2）。每格：選照片、按住錄稱呼、聽一次、按住刪除。改了就存。
- 小孩端：`DeckPickScreen` 最後一格「家人」（至少一張可玩才出現），進去走現有 `DeckScreen`，蓋子、錄自己的聲音照舊。
- 可玩規則：固定槽有照片就可玩（沒錄音播預設稱呼）；自訂槽要照片＋錄音。
- 播音：家長錄音放在 `CardEntry.sound`（叫聲位）；有錄音時 `voice`／`voiceEn` 留空（免得念兩次），沒錄音才放預設稱呼。小孩自己錄的（`RecordingStore`）照舊優先蓋掉 `voice`。
- 家人 Deck **不進 `DeckLibrary.All`**：找一找、配對、摸一摸、數數、拼圖、畫畫第一版抓不到家人卡。`DeckScreen` 翻到底在家人組內繞圈，不會串到別組。

## 驗收

自動：型別檢查 0 錯誤；`grep FamilyLibrary` 只出現在 `FamilyLibrary`、`FamilySlotView`、`DeckPickScreen`、`SettingsScreen`、`BabyAppSceneBuilder`；上述「不改」檔案 `git diff` 為空；8 段語音＋`.meta` 都在；跑完選單 3 的 Console 沒有「找不到欄位」「找不到提示語音 family_」。

人工（Editor Play，2360×1640）：
1. 沒有 `family/` 資料夾時卡片頁**沒有**「家人」格。
2. 長按「設」→「家人卡」→ 8 格 4×2，每格「還沒選照片」；「回設定」回設定頁。
3. 爸爸那格按相簿圖示 → 檔案視窗選一張大 JPG → 縮圖出現、方向正確、狀態「可以玩了（用內建稱呼）」；`family_dad.jpg` 長邊 ≤ 1024；照片沒有變暗或發白（Linear 色彩空間的縮圖）。
4. 檔案視窗按取消：什麼都不變、沒紅字。
5. 卡片頁最後一格「家人」，封面是爸爸的照片；點進去有「？」蓋子，打開聽到合成的「爸爸」。
6. 家長頁按住麥克風錄「把拔」→ 立刻播回、狀態「可以玩了」；小孩端只聽到「把拔」，不再接合成的「爸爸」。
7. 小孩端錄自己的聲音 → 之後先「把拔」再小孩的聲音。
8. 自訂 1 只選照片不錄音：小孩端看不到；錄完就出現，名稱「家人」（開「顯示文字」才看得到）。
9. 家人組滑到底繞回第一張，不跳進動物組；動物組往前滑也不進家人組。
10. 其他六個遊戲都不會出現家人照片。
11. 切英文：沒錄音的固定槽念「Daddy」，家長頁文字全英文；有錄音的照播錄音。
12. 長按橡皮擦：照片、狀態清空，`family_dad.jpg`、`.wav`、`recordings/family_dad_zh.wav`／`_en.wav` 都刪掉；一張可玩的都沒有時「家人」格消失。
13. 停止再 Play：家人卡和錄音都還在。
14. 設定頁「清除錄音」只清小孩的錄音，家人照片與家長錄音還在。

實機：iPad 選照片時是系統 PHPicker、沒有權限對話框、直拍方向正確；Android 13+ 不跳權限（記下是 Photo Picker 還是文件選擇器）；Android 8～12 不跳存取權限詢問且選得到圖（這條是 Android 做法能不能成立的關鍵）。

## 風險（摘要）

- WebGL 整個功能不可用（NativeGallery 與麥克風都沒有）：設定頁的入口在 WebGL 藏起來；決定 iPad 路線時要算進去。
- Android 不是 Google 的 Photo Picker；AAR manifest 帶 `READ/WRITE_EXTERNAL_STORAGE`，上架前要用 Custom Main Manifest 拿掉（發佈前事項）。
- iOS 用途字串是否必要（ITMS-90683）要等實際上傳；沒有 Mac 驗不了。
- Editor 的 `Texture2D.LoadImage` 不套 EXIF，Editor 裡直拍照片可能是橫的；實機由 NativeGallery 原生端修正。
- 換照片要 Destroy 舊的 Sprite 與 texture（`FamilyLibrary.ReleasePhoto`），不然會漏記憶體。
- NativeGallery AAR 與 Unity 6000.5 Gradle 的相容性，第一次出 APK 才知道。

## 第一版刻意不做

相機、超過 8 格、雲端或帳號、家人卡進其他遊戲（第二階段要動 `DeckLibrary` 來源並做方形裁切）、自訂槽打字取名、Android manifest 權限清理。
